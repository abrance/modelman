# OCR Web 界面设计

给 OCR 服务加一个自带页面：**手机拍一张图，得到文字**。现状是服务只有 API，
手机上要么敲 curl，要么装别的工具，所以要一个页面；但不想为此引入新的部署单元、
新的镜像、前端构建链或 node 工具链。

实现与后续变更都按本文件走。服务本身的接口契约见 `services/ocr/README.md`，
系统级设计见 `design.md`。

## 约束

下面每一条都是既有决定推出来的，不是本功能新选的；它们直接决定了方案形状。

| 约束 | 来源 | 对设计的影响 |
|---|---|---|
| 服务只绑 `127.0.0.1:9101` | `deployment.md`（无鉴权服务不直接暴露） | 手机要用必须经云主机 traefik 入口，入口不在本仓库范围内，只能给清单 |
| `AUTH_TOKEN` 当前未启用 | 本项目决定（`design.md` D15） | 挂上入口就是公开的：`/ocr` 谁都能调。影响面被已有的并发上界卡住，要收敛时启用 token 即可（两侧代码已就绪） |
| 运行环境不保证外网可达 | `design.md`（权重随镜像交付的理由） | 页面不得引用任何 CDN、外部字体、外部脚本 |
| 一个服务一个镜像、随镜像交付 | `architecture.md` | 页面编译进二进制，不做运行时挂载、不新增容器 |
| `MAX_SIDE=0`（默认不缩图） | `config.rs`：缩图会抹掉小字号 | 客户端不偷偷压缩图片 |
| 手机照片常 3–8 MB，服务上限 `MAX_IMAGE_BYTES=20 MB` | `config.rs` | 超限要有明确的提示与"压缩后重试"，而不是静默失败 |

## 非目标

- 不做账号体系、多用户、权限。
- 不做前端构建（无 node / vite / 打包器），不做依赖管理。
- 不做 PWA、离线缓存、Service Worker。
- 不改 `/ocr`、`/ocr/batch` 的请求与响应契约。
- 不存图片：历史记录只存文本，服务端不落地任何上传内容。
- 不做服务端模板渲染：页面是静态文件，数据全部由浏览器侧调 API 得到。

## 链路

```
手机浏览器 ──https──► traefik（云主机，仓库外）
                        │
                        └──► 127.0.0.1:9101  ocr 服务
                                 GET  /ui, /ui/app.css, /ui/app.js   （免鉴权）
                                 POST /ocr?model=…                   （需 token）
```

同源调用，所以**不需要动 CORS**（`CorsLayer::permissive()` 保持现状）；
也不需要在页面里配置服务地址，一律用相对路径。

注意页面用的是**绝对路径** `/ocr`，所以 traefik 入口必须把**域名根路径**
转发到 `127.0.0.1:9101`。把服务挂在子路径（如 `https://host/model-ocr/`）
下会让 `/ocr` 解析不到，这一点写在 `deployment.md` 的清单里。

## 后端

### 新增三条路由

| 方法 | 路径 | 内容 | 鉴权 |
|---|---|---|---|
| GET | `/ui` | `index.html`，`text/html; charset=utf-8` | 否 |
| GET | `/ui/app.css` | 样式，`text/css; charset=utf-8` | 否 |
| GET | `/ui/app.js` | 脚本，`application/javascript; charset=utf-8` | 否 |

**免鉴权是刻意的**：页面必须先能打开，才谈得上填 token。`/ui` 只暴露页面结构，
不含任何敏感数据。

### 实现要点

- **编译期嵌入**：`include_str!("../static/index.html")` 等三处。`static/` 因此
  不进镜像，`Dockerfile` 与 `.dockerignore` 都不用改；文件缺失会在编译期报错，
  等于自带一道完整性检查。
- **不加依赖**：不引 `tower-http` 的 `ServeDir`/`ServeFile`，只用现有的
  `axum::response::Response`。
- **响应头**：
  - `Cache-Control: no-cache`。换镜像后手机上刷到旧页面，比多几百字节的请求麻烦得多。
  - `Content-Security-Policy: default-src 'none'; img-src 'self' blob: data:; connect-src 'self'; style-src 'self'; script-src 'self'; base-uri 'none'; form-action 'none'`。
    禁掉一切外部资源与内联脚本，既防第三方注入，也保证不会去拉 CDN。
- 挂到现有的 `open` 路由组（与 `/healthz` 等并列），不进需要鉴权的 `guarded` 组。

## 页面

无构建：一个 `index.html` + 一个 `app.css` + 一个 `app.js`。JS 用普通
`<script defer>` 引入，先不分模块——分模块要 `type="module"` 与相对路径导入，
收益（文件边界）在几百行规模下不明显；等 `app.js` 超过约 500 行再拆成
`api.js` / `render.js`，那时也不需要构建。

### 布局（手机优先）

单页，从上到下三段。宽度 ≥ 640px 时把「结果」与「输入」并排成两列，手机上单列。

| 区域 | 内容 |
|---|---|
| **输入** | 拖放区（也吃点击，展开文件选择）；「拍照」按钮（独立 `input`，带 `capture="environment"`）；档位下拉；token 输入（默认折叠）；多图时的进度 `n/N` |
| **结果** | 每张图一张卡片：缩略图（叠加位置框）+ 文本行（等宽、可选中）+ 单张复制 + 该张耗时与平均置信度；失败时显示错误原因 |
| **操作** | 全部复制、导出 `.txt`、清空结果；历史记录列表（每条：时间、档位、耗时、文本摘要、复制、删除；另有「导出全部历史」与「清空历史」） |

`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`，
触控目标不小于 44px，`env(safe-area-inset-*)` 留出刘海与手势条空间。

### 档位从哪来

启动时读两个**免鉴权**端点，不硬编码任何档位名：

- `GET /models` → 下拉的可选项（`id` 做 value，`label` 做说明文字）；
- `GET /version` → 默认选中项（`default_model`）。

`/version` 失败就选第一项，不阻塞使用。批次进行中改档位只影响后续请求，
**每张卡片记录自己当时用的档位**，展示与导出都用卡片上的值。

### 文本怎么拼

三处输出必须先定死，否则「全部复制」与「导出」会给出一致性不同的结果：

| 输出 | 规则 |
|---|---|
| 单张卡片 | 服务返回的 `results[].text` 按原顺序用换行拼接 |
| 全部复制 | 各张卡片的文本用**空行**分隔，顺序与结果区一致 |
| 导出 `.txt` | 每张图一段：首行 `# <文件名>（<档位>）`，接着该图的文本，段间空行 |
| 导出历史 | 每条一段：首行 `## <本地时间> <档位>（<耗时> ms）`，接着文本，段间空行 |

### 八项功能的行为与边界

| 功能 | 行为 | 边界 |
|---|---|---|
| 拖拽 / 点选 | 选择或拖入 `image/*`；`dragover` 高亮；非图片文件忽略并提示 | 空文件、非图片类型、超大文件都给出提示而不是静默忽略 |
| 粘贴 | 监听 `document` 的 `paste`，取 `clipboardData.items` 里的图片 | 只有文本时不动，让用户正常粘贴到输入框 |
| 拍照 | 独立按钮触发 `capture="environment"` 的 `input` | 桌面浏览器会退化成普通文件选择，属正常 |
| 多图 | **逐张串行** POST `/ocr`，每张出结果立即渲染；顶部显示 `n/N` 进度 | 单张失败只标红该卡片，不中断其余；不并发请求，避免占用多个并发槽位；一次最多排队 **20 张**，超出只取前 20 张并提示（防误选整本相册） |
| 档位 | 启动时用 `GET /models` 填充下拉、用 `GET /version` 的 `default_model` 定默认项（见下文「档位从哪来」） | `/version` 失败就用第一项；`/models` 失败时下拉只剩默认值，不阻塞使用 |
| 一键复制 | 优先 `navigator.clipboard.writeText`；非安全上下文下回退隐藏 textarea + `execCommand('copy')`；仍失败则提示"长按选中文本" | 必须有回退：HTTP 下 `navigator.clipboard` 直接不可用 |
| 位置框 | 按 `bbox` 在缩略图上叠加矩形（`left/top/width/height` 是原图像素坐标）；点击某行文本高亮对应框，点击框滚动到对应行 | 坐标按 `naturalWidth / 显示宽度` 换算；`bbox` 为 `null` 的行不画框 |
| 历史 | 每次成功识别后写入 `localStorage`：时间、档位、耗时、平均置信度、完整文本 | 上限 50 条且总文本 ≤ 256 KB，超出丢最旧；不存图片，因此历史条目不能恢复位置框 |

### 状态与错误

页面状态就是一个数组：每项 `{file, previewUrl, status, result, error, elapsedMs}`。
渲染是"由状态整体重绘"的纯函数，不做增量 DOM 修补——几百行规模下这样最不容易出错。

| 情况 | 表现 |
|---|---|
| 401 | token 输入框自动展开并高亮，提示"需要 token"；已输入的 token 标为无效 |
| 400 且消息含 `MAX_IMAGE_BYTES` | 卡片提示超限，给「压缩后重试」：canvas 缩到长边 2000，**PNG 与 JPEG 各编一次取更小的**（纯色截图上 PNG 可能反而更小且无损，只挑 JPEG 会出现"压完比原图还大"）。解码后仍是**新文件**，精度变化写在提示里。压缩**只做一次**：第二次还超限就给出"仍然超过上限，换一张图或调大 `MAX_IMAGE_BYTES`"，不再提供按钮——否则会变成一个能无限点下去的循环 |
| 400 其它 | 显示服务返回的 `error` 文本 |
| 503 | 提示服务忙，卡片保留「重试」按钮 |
| 网络失败 | 提示不可达，卡片保留「重试」；不自动重试，避免在弱网下叠加请求 |
| `/models` 或 `/version` 失败 | 下拉只剩默认档位，其余功能不受影响 |

### 安全

- **OCR 文本一律经 `textContent` 写入**，绝不用 `innerHTML`：识别内容来自图片，
  等同不可信输入。
- **位置框坐标只能用 CSSOM 设置**（`el.style.left = …`）。CSP 的 `style-src 'self'`
  会拦掉 HTML 里的 `style="…"` 属性，而 CSSOM 赋值不受限制；用模板字符串拼
  `style` 属性的写法会直接看不到框。
- 页面不加载任何外部资源；CSP 再兜一层。
- token 存 `localStorage`，同时接受每次输入。它能在同源脚本被注入时被读走——
  这是"无后端会话的纯静态页"的固有代价，靠"不引第三方脚本 + 严格 CSP"压低，
  文档里写明。**HTTPS 是前提**：HTTP 下 token 明文过网。
- **本次的决定是不启用鉴权**（`design.md` D15）：页面与 API 就那样对公网开着，
  任何能访问入口的人都能调 `/ocr`。上界（`MAX_CONCURRENCY=2`、`LIMIT_CONCURRENCY=8`、
  compose 的 `cpus=2/memory=1500M`）保证被滥用时对方拿到 503，而不是把共享主机拖垮。
- 要收敛时：`AUTH_TOKEN` 一开，页面会在 `localStorage` 存一份并在每次请求带上，
  401 时自动展开输入框——**不需要改代码，也不需要重新设计**。
- **HTTPS 仍然是前提**，与鉴权无关：HTTP 下 `navigator.clipboard` 不可用，
  「一键复制」会失效；另外手机上填任何凭据都是明文过网。

## 测试

| 层 | 内容 |
|---|---|
| Rust HTTP 测试（`tests/http.rs`） | `/ui` 返回 200 且 `content-type` 为 `text/html` 且响应体含 `<title`；`/ui/app.js`、`/ui/app.css` 的 content-type 正确；`/ui` 与静态资源在设置了 `AUTH_TOKEN` 时**仍然免鉴权**，而同场景下 `/ocr` 返回 401；三条路由都带 CSP 与 `no-cache` 头 |
| 冒烟（`services/ocr/smoke.sh`） | 追加 `curl -fsS …/ui` 断言响应含 `<title`，确认镜像是真的带上了页面 |
| 契约测试 | 不动：`/ocr` 响应结构未变，基线无需重生成 |
| 手动验收 | 见下 |

**不引前端测试框架**：没有构建产物、没有模块系统，页面逻辑（bbox 换算、文本合并、
档位参数拼接、历史裁剪）保持薄到不值得引 vitest/jsdom。等 `app.js` 拆模块时
再评估。

取而代之的是一个可选的验收脚本：`services/ocr/tools/ui_acceptance.py`，用
Playwright 驱动真实 Chromium 把上面的手动清单跑一遍（默认场景 19 项，另有
`auth` / `too-large` 两个需要特殊环境变量的场景）。它**不进 CI**，也不在
`requirements-dev.txt` 里，跑之前自己装一次 playwright。

三处不能自动化、只能真人拿手机过一遍：真的调起相机、HTTPS 下的剪贴板行为、
刘海屏幕下的安全区。

验收清单（`core` 场景已覆盖 1、3–8 项；2 需要真手机）：

1. 点选、拖拽、粘贴（Ctrl+V）三种方式都能出文字；
2. 手机点「拍照」直接调起相机，拍完能出文字；
3. 一次选 3 张，进度从 1/3 走到 3/3，其中一张故意用非图片文件时只有它标红；
4. 档位切到 `v6tiny` 后请求里确实带了 `model=v6tiny`；
5. 「全部复制」在 HTTPS 下成功，在 HTTP 下走回退路径也成功；
6. 点击文本行，对应位置框高亮；缩放窗口后框仍对齐；
7. 刷新页面后历史还在，导出 `.txt` 内容与结果一致；
8. 清掉 token 后请求返回 401，页面正确提示并要求输入 token；
9. 超限的图点「压缩后重试」能出文字；两次都超限时给出明确文字，且按钮不再出现。

## 风险

| 风险 | 影响 | 处置 |
|---|---|---|
| 入口不带鉴权就开放 | 能访问的人都能调 `/ocr`，占用共享 CPU | 有意接受（D15）。并发上界与 compose 限额把影响面卡在"对方拿到 503"；要收敛时启用 `AUTH_TOKEN`，代码已就绪 |
| token 存在浏览器里 | 同源 XSS 可读走 token | 不引第三方脚本、严格 CSP、`textContent` 渲染；HTTPS 必须 |
| 手机缓存旧页面 | 发版后行为和接口对不上 | 三条路由 `no-cache` |
| 大图上传慢或超时 | 用户以为服务坏了 | 显示文件大小；超限给压缩重试；503/网络失败给重试按钮 |
| traefik 入口与证书不在仓库里 | 无法用自动化保证 | 只在 `deployment.md` 给操作清单，不试图代管 |
| 位置框在超大图上目视偏差 | 影响可用性 | 按 `naturalWidth` 换算，而不是按 `clientWidth`；验收第 6 条覆盖 |

## 实施顺序

每步都可独立验证，前四步之后就已经"能用"。

1. 后端三条路由 + 响应头，配 `tests/http.rs` 四个断言；
2. `index.html` 骨架与 `app.css`（输入 / 结果 / 操作三段，手机优先）；
3. `app.js`：API 客户端 + 单图流程 + 401 提示；
4. 多图串行 + 进度 + 单张错误隔离；
5. 档位下拉（`GET /models` 填充可选项、`GET /version` 定默认项）；
6. 位置框叠加 + 行高亮联动；
7. 复制（三级降级）；
8. 历史记录 + 导出；
9. `smoke.sh` 与四份文档；
10. 跑 `tools/ui_acceptance.py`（core / auth / too-large 三个场景），再拿真手机过一遍不能自动化的三项（调起相机、HTTPS 剪贴板、安全区）。
